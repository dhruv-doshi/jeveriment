# From the fixed-pool pilot to the RAG experiment

`feature/production-rag` is a clean branch for the five-dataset study. The BEIR/SciFact pilot, its commands, configs, prompts, and task-specific tests remain on `feature/parallel-jev` and in Git history. Existing run data in the other worktree was not moved or rewritten. Old pilot artifacts are not accepted as new RAG artifacts without an explicit converter.

The new branch retains `io.py` for canonical hashes and atomic JSON writes, `metrics.py` for ranking metrics, `stats.py` for paired statistics, and `ledger.py` for the shared budget. Pilot-specific provider and model code was removed. The replacement provider, model, retrieval, and evaluation paths live under `rag/` with new tests.

The new entry point is `jev-eval rag`. It includes source audit/preparation, dense indexing, a dry-run and executable matrix, reporting, trace export, a service endpoint, and a local fault-injection load command. The config selects MIRAGE, CLERC, HotpotQA, QASPER, and KILT-FEVER; BM25, Qwen dense, and hybrid retrieval; retrieval-order, MiniLM, BGE, Qwen, and standard JEV reranking; and OpenRouter Kimi K2.5 for fixed generation under a $50 ceiling. Dataset source revisions, provider route, model revisions, and account prices/rate limits must be frozen before a real run.

`rag/contracts.py` and `rag/artifacts.py` establish the new stage record and content-addressed JSON format. The first artifact schema is version 1. The end-to-end path, parallel query workers, replay, shared spend/rate gates, metrics, and reports are implemented and tested with local fixtures. Real corpora, local model weights, and live provider calls have not been exercised; see the [development report](DEVELOPMENT_REPORT.md). The full experiment awaits the owner's instruction.
